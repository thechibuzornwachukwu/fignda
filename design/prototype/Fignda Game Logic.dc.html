Game logic

How a Fignda game is built, played and scored. Every puzzle format plugs into the same pipeline.

Pipeline

Category Topic Puzzle type Answers Validation Score Result

The shell (topic picker, progress, timer, hints, results) never changes. Only the puzzle type does.

Data model

Game {
  id          "bible"
  type        "hidden-words"      // which engine runs it
  category    "Bible"             // Bible, Science, AI, History, General, Custom
  title       "Books of the Bible"
  difficulty  "Easy" | "Medium" | "Hard"
  content     { text, dict }      // type specific input
}

Engine.build(game)  -> Puzzle { answers[], render data }
Engine.check(puzzle, selection) -> Answer | null

Session {
  found{}, hints, startedAt, endedAt, finished
}
Categories Bible, Science, AI, History, General and Custom. A category is a filter and a label. It holds no logic.
Game types Hidden words ships first: answers hide inside a paragraph across word breaks. Planned: missing letter, odd one out, anagram paragraph.
Topic selection Pick a curated game or type any topic. Links like ?game=bible open a game directly.
Puzzle generation Curated games are written by hand. Custom topics ask a language model for a paragraph and a word list, then pass through the same build step.
Answer generation The text is reduced to a letter stream (lowercase, no spaces or punctuation). Each dictionary word is searched in that stream. Only words that truly occur become answers, so the count is always honest. Generated puzzles need at least 4.
Difficulty Set by answer count, text length and how many answers cross a word break. Easy: under 10 answers, short text. Hard: 20 or more, long text.
Validation A drag selects a range in the letter stream. If those letters equal an unfound answer, it is found. Already found shows a note. Anything else is quietly rejected.
Scoring 100 per answer, minus 25 per hint. Finding all answers adds a time bonus of 600 minus seconds taken, floored at 0.
Progress Found over total, a bar, a found list and remaining answers shown only by letter count.
Completion A game ends when every answer is found or the player taps Finish. Results show score, found and time. Missed answers are shaded in the text.
Hints Marks the first letter of a random remaining answer. Unlimited, each one costs points.
Timer Counts up from the first render. Stops on completion. No countdown, so nobody is rushed.

Adding a game type

01Name it. Register a new type key, for example "missing-letter".
02Write build. Turn content into answers and render data.
03Write check. Map a player action to an answer or null.
04Add a board. One view for the puzzle area. The shell handles the rest.
